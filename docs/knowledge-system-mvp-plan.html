PERSONAL KNOWLEDGE ENGINE · MVP PLAN

个人知识系统 · MVP 架构与落地方案

目标：从多设备、多应用捕获知识（文本 / 网页链接 / 音频 / 手写）→ AI 总结为原子笔记 → 依据知识科学理论构建持续生长的知识网络。本方案定义 MVP 的技术选型、科学依据、建链与生长机制、10 周落地路线与 30 天验收指标。

范围：MVP · 本地优先 · 6 类采集源 周期：10 周落地 北极星指标：回取率 版本：v1.1

0执行摘要与核心决策

六个决策定义了整个 MVP 的边界，后续所有设计都服从这些决策。
编号决策内容与理由
D1本地优先图谱、向量、FSRS 调度全部本地运行，数据不出设备。LLM 默认走云端 API（DeepSeek/Qwen，成本低），敏感来源（微信、聊天记录）强制切本地模型。隐私是底线，也是长期信任卖点。
D2不引入图数据库MVP 用 SQLite + 递归 CTE 承担图遍历。节点量 <10⁵ 时性能足够，且零运维、单文件备份。迁移触发条件：节点 >10⁵ 或需要实时图算法（社区发现/PageRank），再评估 Neo4j 或图专用层。
D3科学建链网络 = 原子节点 + 9 类类型化命题边 + 独立前提 DAG。所有链接必须可解释（带理由）可审计（带置信度与来源），拒绝"相似就拉线"的随意构建。依据：同化理论、概念图、知识空间理论（见 §1）。
D4人工在环建链走"LLM 建议 + 人工确认"：高置信（≥0.85）自动入图可一键撤回；中置信进建议箱；低置信丢弃。每周 15 分钟确认建议箱，反馈样本回流优化提示词。
D5生长是主引擎系统不是记录工具而是"知识生长引擎"：FSRS 每日回取 + 每周自动综合 + 冲突检测。北极星指标是回取率（到期节点被实际回顾的比例），不是存储量。
D6采集增量扩展 · 多模态归一全设备是长期目标，MVP 接 6 类源：文本类（浏览器、剪贴板、飞书）+ 链接提取 + 音频转写 + 手写识别。所有源统一为"采集队列 + 适配器"；音频、手写先转为文本中间态（ASR 转写 / OCR 识别），之后与文本走完全相同的建链与生长流程，网络构建的科学性不受输入模态影响。

1科学依据：知识网络为什么这么建

"不断生长的知识网络"必须有可追溯的理论支撑。以下 8 个理论与模型直接决定系统的建链规则、边类型、调度算法与综合机制，每一行都对应一条具体的设计规则，而非装饰性引用。
理论 / 模型来源核心主张落到系统的设计规则
同化理论（Ausubel）Ausubel, 1968 有意义学习 = 新知识连接到已有认知结构中相关（上位）概念；孤立信息只能机械记忆、迅速遗忘。 入图门槛新节点必须与 ≥1 个已有节点建立命题链接，否则进入"待连接池"，不直接入图。网络只在"同化"中生长。
概念图（Novak）Novak & Gowin, 1984 知识的最小单元是命题：概念 + 连接词 + 概念；概念图的网络结构本身就是意义的表征。 边类型所有边必须是带类型的命题（9 类有向边），每条边附一句话理由。禁止无意义的"相关"连线。
卡片盒笔记法（Zettelkasten）Luhmann；Ahrens, 2017 原子笔记 + 双向链接 + 用自己的话重写；系统价值来自不同笔记间的"意外连接"与新观点涌现。 原子性一节点一主张（≤200 字）；出链 ≥1；反链自动维护；把"综合产出新节点"设为系统目标而非副作用。
知识空间理论（KST）Doignon & Falmagne, 1999 知识可建模为"前提结构"：概念之间存在学习依赖关系（先决条件），学习顺序应由结构决定。 前提 DAG独立维护 prerequisite_of 边构成的有向无环图；回取与综合的主题顺序由图推导，而非时间顺序。成环即报错。
检索练习效应Roediger & Butler, 2011 主动提取记忆本身会强化记忆；重读的巩固效果远弱于检索。 回取形式到期卡片先给标题+提示让大脑先检索，再展示正文；成功/失败反馈写回调度器。
间隔重复 / 记忆模型Ebbinghaus, 1885；FSRS（开源，Anki 已集成） 遗忘可预测，最优复习间隔可由机器学习参数化的记忆模型计算（难度/稳定性/可回忆概率）。 调度每个节点挂 FSRS 状态（难度、稳定性、到期日、复习次数、遗忘次数），到期自动进入每日回取队列。
合意困难（Desirable Difficulties）Bjork, 1994 适度增加提取难度能增强长期记忆保持。 难度分级回取难度随稳定性上调（提示越来越少）；连续答对的节点拉长间隔，避免"熟练感假象"。
GraphRAG（工程前沿）Microsoft, 2024 对知识图谱做社区检测与分层摘要，能显著提升 LLM 检索与生成质量、降低幻觉。 综合机制每周综合基于图社区（密度聚类）而非关键词搜索；图谱同时是检索基础设施与生长证据。
科学链条总结：同化理论决定为什么连（新知识必须挂到已有结构上）→ Novak 概念图决定连成什么（命题化有向边）→ KST 决定往哪个方向连（前提依赖 DAG）→ 检索练习与 FSRS 决定如何强化连接（按遗忘曲线回取）→ GraphRAG 决定网络如何产出（社区级综合）。这条链就是"科学构建，而非胡乱构建"的完整依据。

2MVP 范围

明确"做什么"与"坚决不做什么"，避免范围蔓延拖垮 MVP。

✅ MVP 包含（6 类采集源）

  • 浏览器阅读：Chrome/Edge 扩展，一键收藏 + 划词捕获（网页正文、划线片段）
  • 剪贴板：系统剪贴板守护，文本/代码即复制即捕获；自动识别 URL 并路由到链接提取器
  • 飞书：开放平台 API 拉取你授权的文档 / 消息（你的日常主阵地）
  • 链接提取：从任意平台（微信文章、知乎、B站、公众号等）复制链接 → 抓取网页正文 → 总结；静态提取失败时用无头浏览器兜底
  • 音频：录音设备导入 / 上传音频文件（会议、口述、播客）→ ASR 转写 → 自动总结为知识
  • 手写：拍照 / 扫描 / 上传手写笔记 → OCR 手写识别 → 校对 → 自动总结为知识
  • 加工：多模态统一中间态（正文 / 转写 / OCR 文本）→ LLM 原子化 → 去重 → 质量门
  • 建链：召回 + LLM 命题判定 + 建议箱 + 图谱视图
  • 生长：FSRS 每日回取 + 每周综合 + 冲突检测 + 指标面板

🚫 MVP 不做（留到后续）

  • 手机端 App / 系统级全量采集（OS hook、无障碍）
  • 微信收藏、邮件、视频笔记、PDF 批注（源 #7+，架构已预留适配器）
  • 多端同步 / 云服务 / 协作共享
  • 图数据库、分布式、移动端
  • 自动发布 / 对外产品化（先跑通个人闭环）

3数据模型

所有科学规则都落在这三张表上。schema 用 SQLite 表达，向量由 sqlite-vec 的 vec0 虚拟表承载。

3.1 三张核心表

表关键字段说明
nodes id · type(concept/claim/source/question) · title · body(≤200 字主张) · source_ref · embedding(vec0) · recall_state(JSON: difficulty/stability/due/reps/lapses) · status(draft/active/archived) 原子笔记本体。embedding 由本地 BGE-M3 生成；recall_state 由 FSRS 维护。
edges id · src_id · dst_id · rel_type(9 类) · rationale(LLM 一句话理由) · confidence(0–1) · confirm_status(auto/pending/approved/rejected) · created_at 命题化有向边。conflict 检测与前提 DAG 校验都在这层做。
sources id · kind(url/clipboard/message/audio/handwritten) · raw_path(原始文件/录音/图片归档) · text_extracted(转写或 OCR 中间文本) · fingerprint(去重指纹) · title · captured_at 原始材料归档。音频存原始录音 + 转写文本；手写存原图 + OCR 文本；fingerprint 基于 text_extracted 计算，实现跨模态去重（辅以 embedding 阈值）。

3.2 九类命题边（Novak 命题 × 工程实现）

rel_type含义示例用途
implies蕴含 / 因果A 导致 B；A 蕴含 B因果链推理
supports支持 / 证据实验数据支持该结论证据链
contradicts反对 / 矛盾新论文结论与旧笔记冲突触发冲突报告
exemplifies实例 / 例证该概念的一个具体案例抽象 ↔ 具体
refines细化 / 精化旧结论的新限定条件知识演化
prerequisite_of前提 / 先决先理解 A 才能理解 BKST 前提 DAG，决定学习顺序
contrasts对比 / 区分A 与 B 在维度 X 上不同辨析
merges同义合并两个节点描述同一主张控制膨胀、剪枝
relates弱关联共享主题但关系待定必须人工确认，防"假链接"

6建链引擎（科学建链流水线）

这是"科学依据"的工程化落地：每一步都有明确规则、置信度门控和人工兜底。

6.1 流水线

前置归一化：所有输入——网页正文、ASR 转写文本、OCR 识别文本、剪贴板片段——在进入本流水线前已统一为同一形态的文本中间态，因此建链规则对所有模态完全一致，知识网络的结构不因来源是音频还是手写而改变。

  1. 召回：新节点入库 → 本地 BGE-M3 编码 → vec0 相似召回 Top-20；FTS5 关键词召回 Top-10；并集去重
  2. 规则层：实体共现（概念名精确匹配）、同源文档内建链、标题/标签命中——规则命中直接生成候选
  3. LLM 命题判定：对每个候选对，LLM 输出结构化 JSON：{rel_type, confidence(0–1), rationale(一句话理由)}；候选对 <9 类之一或无法判定 → 返回 null 丢弃
  4. 门控：confidence ≥0.85 → 自动入图（可在界面一键撤回）；0.5–0.85 → 建议箱待确认；<0.5 → 丢弃并记日志
  5. 前提 DAG 校验：prerequisite_of 边写入前做环检测，成环则降级为 relates 并告警（KST 一致性要求）
  6. 孤儿规则：入库 48h 仍无边 → 标记"待连接"，进入每周综合任务的优先处理队列；30 天仍孤立 → 提示合并或归档

6.2 人工在环

  • 建议箱每周确认一次（约 15 分钟），操作：接受 / 拒绝 / 改类型；
  • 所有人工操作记录为样本，周期性（每 2 周）用于改进 LLM 判定提示词；
  • 图谱视图支持任意节点的出链/反链/邻域展开，人工可随时补链——补链即最高优先级入图。
防"假链接"红线：embedding 相似 ≠ 知识关系。向量相似只负责召回候选，最终成链必须由命题判定给出可解释的 rel_type + rationale。这条红线直接来自 Novak 命题观与"拒绝随意连线"的原则。

7生长机制（系统的核心价值层）

三个机制 + 一个面板。设计原则：回取是推送不是打卡，综合是产出不是报表。

每日回取（5 分钟）

  • FSRS 到期节点 → 卡片队列，先显示标题 + 提示（检索练习），作答后展开正文对照
  • 自评：记住 / 模糊 / 忘记 → 写回 FSRS 更新难度与稳定性
  • 忘记的节点 → 触发"重读 + 重新精炼"（进入草稿箱二次加工）
  • 连续答对 → 拉长间隔（合意困难，防熟练感假象）

每周综合（30 分钟）

  • 图社区检测（Louvain 或高频共现）→ 选出密度最高的社区
  • LLM 基于社区内全部节点生成综述 / 提炼新主张（GraphRAG 思路）
  • 综合产物作为新节点（source=综合）挂回图，并链接社区代表节点
  • 综合产出数 = 网络"真正生长"的直接证据，写进指标面板

冲突检测

  • contradicts 边落库时生成"矛盾报告"：双方主张 + 各自证据链
  • 可选动作：保持并存（标注未决）/ 触发定向检索 / 删除一方
  • 解决结果记录在边上，形成"知识演化历史"

指标面板

  • 结构：节点数 / 边数 / 链接密度 / 孤儿率 / 图直径 / 中心性
  • 行为：回取完成率 / FSRS 稳定性趋势 / 遗忘率
  • 产出：每周综合篇数 / 综合节点被引用次数

8落地路线图（10 周）

10风险与对策

风险等级对策
隐私泄露（全设备数据聚合）高Local-first 架构；敏感源（IM/聊天/录音/手写）强制本地模型；导出加密；白名单机制控制云端调用
音频隐私（录音/语音是最敏感数据）高ASR 默认本地（FunASR/SenseVoice）；录音文件本地归档并可加密；云端转写需显式逐条授权
采集源 API 变更 / 失效高统一采集队列 + 适配器模式；单源失效不影响其他源；扩展与剪贴板源不受第三方 API 约束
链接抓取反爬 / 平台限制高trafilatura + Playwright 多级降级；抓取失败保留链接与标题并标记"待处理"，不静默丢弃；遵守 robots 与平台规则
手写识别质量（中文手写误差高）中OCR 置信度分级：低置信直接进人工校对队列；校对记录回流优化识别与 LLM 纠错提示词
LLM 摘要质量（同质化/浅层化）高质量门 + 草稿箱；提示词版本管理；人工确认样本每两周回流优化
只存不用（用户粘性）高回取是推送式（每日 5 分钟）；综合产出可见；指标面板展示生长成果
图谱膨胀 / 链接劣化中孤儿回收；merges 合并；30 天孤立节点归档；链接密度上限告警
单一依赖（sqlite-vec 维护状态）中向量列可通过存储抽象迁移 LanceDB；schema 与业务代码解耦
FSRS 参数未优化低FSRS 官方提供基于复习日志的参数优化工具，30 天后用真实数据训练
